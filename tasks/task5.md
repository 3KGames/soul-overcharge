# Task 5 — Стейты: масса, вызов шинного API, `dt`, downforce

Зависит от: task 2, task 3, task 4.

## Что сделать

### 1. Эффективная масса
```csharp
float effMass = _physicsData.BaseMass + _engine.EngineMass;
```
Раньше был ещё член `+ _engine.Inertia * (ratio/R)²` (отражённая инерция двигателя).
**Убираем — и это правильно:** в новой схеме инерция мотора уже учитывается через сцепление,
дублировать не надо.

`ForceMode.Acceleration` сохраняется, `rb.mass` не трогаем. `BaseMass` остаётся
единственным источником массы в коде.

### 2. Шинный расчёт вызывается через `DrivetrainService`
Вместо локального блока с `tireStiffness = 5000` / `maxGrip = 15000` — вызов метода из task 4.
Локальные `tireStiffness` / `maxGrip` из стейтов убрать (закомментированные строки не трогать!).

### 3. `Time.fixedDeltaTime` → `dt`
Оба стейта в `MoveRotation` используют `Time.fixedDeltaTime`, хотя `Tick` уже получает `dt`.
Значения совпадают, но источник истины должен быть один.

### 4. `Downforce` в `DriveCarState`
Сейчас `Downforce` применяется в `DriftCarState` и **не применяется** в `DriveCarState` —
расхождение поведения между состояниями. Добавить.

`Downforce` в дрифте применяется уже после шинного расчёта, поэтому на сцепление в этом шаге
не влияет. Это не чинится (см. отложенные проблемы), но порядок стоит сделать одинаковым
в обоих стейтах.

### 5. Прочее
- В `DriftCarState` убрать голый блок `{ }` (строки 96–120), оставшийся от переписывания —
  это просто бессмысленные скобки.
- `DriveCarState`: `turnRate` считается через `rb.linearVelocity.magnitude`, а `turnRadius`
  через `forwardSpeed`. В дрифте для поворота стоит `safeTurnRadius` (клампит ноль),
  в дrive — нет. Привести к одному виду.

### Не трогать
- Закомментированные блоки (старый код) — по решению пользователя не удаляем.
- Нитро (`inputData.TorqueMultiplier`) — отложено.
- `Offroad` / `NoSouls` в продольную тягу — отложено.
- `maxGrip` / кламп сцепления — отложено.
