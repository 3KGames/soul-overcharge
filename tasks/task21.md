# Task 21 — Значения в ассетах и верификация торможения

Статус: `[x]` (ассеты и статика; `dotnet build` и play-mode не гонялись) ·
Зависит от task 20

Фактически записано: `CarPhysicsData.asset` → `brakeTorqueNm: 12000`,
`driftBrakeTorqueNm: 4000`; `Drivetrain.asset` → `maxLongitudinalGrip: 26000`.
Расчёт и результаты статических проверок — в `tasks/tasks.md`, раздел
«Протокол реализации задач 20–21».

## Цель

Записать осмысленные значения тормозных параметров в ассеты и проверить, что
торможение соответствует контракту task 20.

## Часть 1 — значения в ассетах

`brakeForce: 30` в `Assets/Game/Data/CarPhysicsData.asset` заменить на
осмысленное значение в единицах, выбранных в task 20. Если в task 20 введено
новое поле — добавить его ключ в ассет, старый `brakeForce` удалить, чтобы не
оставить мёртвый ключ с неверной трактовкой.

Значение подобрать так, чтобы замедление на полном `Brake` попало в
**25–30 м/с²** при `baseMass: 880` и `wheelRadius: 0.288`.

`driftBrakeForce: 10` — оставить, но задать осмысленное значение в тех же
единицах. Соотношение Drive/Drift сохранить примерно 3:1, как сейчас
(`30` / `10`), если task 20 не задало иного.

`Drivetrain.asset` дополнить новыми ключами, если в task 20 добавлены
параметры сцепления или предела тормозного момента.

## Часть 2 — статическая верификация

Без запуска Unity и без `dotnet build` — по прямому указанию пользователя
сборка не прогоняется.

Проверить грепом и чтением:

1. `BrakeForce` и `DriftBrakeForce` имеют хотя бы по одному потребителю
   вне `CarPhysicsData.cs`.
2. Ни одно из четырёх мёртвых полей не осталось в состоянии «объявлено, но
   не используется» сверх оговорённого в task 20 (пункт 8).
3. В `DriveCarState` и `DriftCarState` тормозной момент вычисляется из
   `inputData.Brake` и передаётся в шинную петлю.
4. Ни в одном стейте не появилось `AddForce` в отрицательном продольном
   направлении.
5. Закомментированные блоки `DriveCarState.cs:83–95` и `134–161` побайтово
   не изменились.
6. Все новые SO-поля имеют `[SerializeField]`.
7. `ApplyLateralFriction`, `GetTurnRadius`, `GetSteeringAngle`,
   `FmodEngineSound.cs`, `TachometerController.cs` не тронуты.
8. Скобки сбалансированы в каждом изменённом файле.
9. `git diff --stat` показывает только файлы из скоупа task 20.

## Часть 3 — расчётная проверка без запуска

Посчитать руками и записать в `tasks/tasks.md` ожидаемую физику, чтобы
пользователь мог сверить после ближайшего запуска Unity:

- замедление на полном `Brake` при 100 км/ч;
- пройденное до полной остановки расстояние;
- обороты двигателя при полном `Brake` на первой передаче — не должен
  уходить в минус или ниже `StallOmega`;
- что происходит с `DrivenWheelsOmega` при полном `Brake` — должен
  остаться положительным (признак отсутствия блокировки).

## Критерии приёмки

1. Оба тормозных параметра присутствуют в ассете в осмысленных единицах, их
   значения дают замедление 25–30 м/с² на дефолтах.
2. Проверки части 2 пройдены, результат зафиксирован в `tasks/tasks.md`.
3. Расчётная проверка части 3 выполнена и записана.
4. `dotnet build` — 0 ошибок и 0 новых предупреждений CS.
   **Сборка запускается только с явного разрешения пользователя**; без него
   пункт остаётся невыполненным и помечается в доске.
5. Play-mode проверка не выполнена и отмечена как требующая запуска Unity
   пользователем.
