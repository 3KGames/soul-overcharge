# Task 18 — Отсечка оборотов как срез топлива, а не зажим числа

## Контекст

Сейчас в `EngineService.UpdateAngularSpeed` стоит жёсткий зажим
`angularSpeed = Mathf.Min(MaxOmega, angularSpeed)` (task 15). Он держит мотор ровно
на 7500 и мёртво. Реальные отсечки так не работают: ЭБУ над порогом **срезает впрыск
топлива**, момент пропадает, мотор падает на трении, впрыск возвращается, мотор
снова растёт. Получается заметная дрожь — именно то, что хочет пользователь.

Порог остаётся существующим `MaxOmega`. Отдельный объект-«ограничитель» не создаётся.

## Поведение, которое требуется

**1. Новый настраиваемый параметр — длительность среза топлива.**

Добавить в `EngineSO` и `EngineModel` поле `RevLimiterCutTime` (секунды, дефолт `0.06`).
По правилу проекта поле обязательно с `[SerializeField]`, иначе Unity его не увидит.
Прогнать значение в конструктор `EngineModel` по образцу остальных полей.

Также дописать `revLimiterCutTime: 0.06` в `Assets/Game/Data/Engine.asset`.
Без этого значение в ассете будет 0 и отсечка не заработает.

**2. Состояние отсечки живёт в `EngineService`.**

Одно поле — остаток времени среза в секундах, изначально 0.

**3. Логика, вычисляемая один раз за физический шаг, по RPM на начало шага:**

```
остаток -= dt
если остаток > 0                          -> срез АКТИВЕН, момент двигателя = 0
иначе если RPM >= MaxOmega и газ > 0.01   -> запустить срез: остаток = RevLimiterCutTime,
                                               момент двигателя = 0 на этом шаге
иначе                                      -> срез НЕ активен, обычный момент
```

**4. Срез обязательно гейтится по газу.** Если газа нет, отсечка не работает, и идёт
обычное торможение двигателем. Без этого гейта при понижении передачи сцепление будет
постоянно упирать мотор в порог и получится непрерывный стрёкот вместо редкого
толчка. Порог газа — `0.01`, как уже принято в проекте (`brake > 0.01f` в
`TransmissionService.UpdateEngagement`).

Побочный эффект гейта: при удержании газа в слишком низкой передаче мотор будет
дребезжать у отсечки непрерывно, пока машина не замедлится. Это **правильное**
поведение — в настоящей машине так же.

**5. Зажим остаётся, но как страховка с запасом, а не как основной механизм.**

Заменить `Mathf.Min(MaxOmega, angularSpeed)` на
`Mathf.Min(MaxOmega * RevLimiterSafetyFactor, angularSpeed)`, где
`RevLimiterSafetyFactor = 1.15f`.

Смысл: мотор **легитимно** уходит выше `MaxOmega` в фазе впрыска — это и есть
дрожь, и она должна быть видна. Страховка нужна только на случай численного выброса.
Множитель допустимо сделать `private const` в `EngineService` с комментарием: это
числовая страховка, а не параметр настройки. Если программер предпочтёт вынести в SO —
тогда обязательно дописать и в `Engine.asset`.

**6. Момент сгорания должен обнуляться, а не зажиматься.**

Обнуление применяется к `engineTorque` ДО вычитания трения и момента сцепления, чтобы
на коленвале остались только трение и насосные потери:

```
torqueEffective = engineTorque - engineFriction - clutchTorque
```

Нулевой двигательный момент в этой формуле и даёт падение на одном трении.

## Ориентиры по числам (проверить после реализации)

При `Inertia = 0.112`, `MaxOmega = 785.4 рад/с` (7500 об/мин), `f(785.4) = 50.5 Н*м`:

- фаза среза (момент 0): `dω/dt = -50.5/0.112 = -450 рад/с² = -4302 об/мин/с`, за кадр 20 мс `-86 об/мин`
- фаза впрыска (полный газ): чистый момент `80.5 - 50.5 = +30.0 Н*м`,
  `dω/dt = +2557 об/мин/с`, за кадр `+51 об/мин`
- при `RevLimiterCutTime = 0.06` размах ожидается в пределах 200–300 об/мин,
  частота около 6 Гц

Падение в полтора раза быстрее подъёма, потому что трение съедает 50.5 из 80.5 Н*м.
Поэтому осцилляция асимметричная: резкий спад, пологий подъём. Это нормально.

## Куда именно встроить

Точка принятия решения — момент, когда в `DriveCarState.Tick` вызывается
`_engine.CalculateTorque(inputData.Throttle)`. Там уже есть и `throttle`, и `dt`,
и текущие обороты. Обнуление момента обязано произойти **до** строки
`torqueEffective = engineTorque - engineFriction - clutchTorque`.

Форма можно выбрать любую из двух, обе допустимы:
- добавить параметр `dt` в `CalculateTorque` и вести таймер внутри;
- отдельный метод `Tick(float dt, float throttle)` в `EngineService`, вызываемый из
  стейта перед `CalculateTorque`, а `CalculateTorque` читает признак среза.

Предпочтительнее первый вариант — меньше точек сцепки в стейтах. Но если выбран
второй, то **`DriftCarState` тоже обязан вызывать новый метод**, иначе в дрифте
отсечка не будет работать. Проверить оба стейта.

Найти и обновить ВСЕ места вызова `CalculateTorque` в проекте. Их ровно **четыре**
(проверено грепом, не искать вслепую):

| файл | строка | вызов |
|---|---|---|
| `Assets/Game/Car/Controller/CarPhysics/States/DriveCarState.cs` | 66 | `CalculateTorque(inputData.Throttle)` |
| `Assets/Game/Car/Controller/CarPhysics/States/DriftCarState.cs` | 74 | `CalculateTorque(inputData.Throttle)` |

### Отдельно про `AccelerationGraphWindow`

Вызовы на строках 254 и 268 идут без контекста газа из инпута и без `dt` от физики.
Если отсечка живёт внутри `CalculateTorque`, редакторный график начнёт её прогонять
и вид кривых изменится. Это **нежелательно**: график задуман как инструмент стационарного
подбора параметров, и его выход уже принимался в task 9.

Обязательное требование: `AccelerationGraphWindow` должен продолжить считать
**без отсечки**. Добиться можно двумя способами — на выбор:

- **Способ A (предпочтительный):** отсечку вынести в отдельный метод `EngineService`,
  а `CalculateTorque` оставить чистым. Тогда сигнатура `CalculateTorque` не меняется
  вообще и стейты правятся одним вызовом нового метода рядом.
- **Способ B:** добавить в `CalculateTorque` необязательный параметр, отключающий
  отсечку, и в графике передавать его как отключённый. Тогда правятся и строки графика,
  но чистота `CalculateTorque` страдает.

Способ A предпочтительнее, потому что сохраняет разделение «чистый расчёт» против
«расчёт с учётом состояния», как уже сделано в `TransmissionService`, где
`CalculateClutchTorque` чистый, а `engagement` считается в `Tick`.

- `FmodEngineSound.cs` не изменён.
