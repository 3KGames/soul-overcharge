# Task 19 — Починить `AccelerationGraphWindow`

## Контекст

График разошёлся с игрой и содержит три ошибки расчёта плюс одну ошибку отображения.
Правки в саму физику машины НЕ входят — только редакторный инструмент.

Пользователь принял решения:
- кривая передачи должна **явно показывать отсечку**: за порогом ускорение падает
  до отрицательного, провал виден;
- `Simulate()` нужно просто синхронизировать с игрой, без других изменений;
- `_maxSpeed = 70` и `StopSpeed = 250` НЕ трогать — диапазон редактируется руками.

---

## Ошибка 1. `maxRpm` в подсказке считается неверно (строка ~570)

```csharp
float maxRpm = _engineSO != null ? 30f * Mathf.PI * _engineSO.PistonMaxSpeed / _engineSO.PistonStroke * 30f / Mathf.PI : 0f;
```

В формуле `MaxOmega = 1000 * П * PistonMaxSpeed / PistonStroke` потерян множитель
`1000f`. Сейчас выходит `30 * П * 0.02/0.08 * 30/П = 225`, а должно быть `7500`.
Подсказка показывает `RPM: 5826 (max 225)`.

**Исправить так, чтобы считалось через ту же формулу, что и в `EngineService`,
без дублирования константы.** Предпочтительно взять значение из уже существующего
`_evalEngine.MaxRPM` — сервис уже создаётся и переиспользуется, лишних полей не
потребуется. Если `_evalEngine` в этот момент может быть не создан — создать через
тот же путь, что и в `EvaluateAccelInGear`, и не плодить третью реализацию формулы.

---

## Ошибка 2. Ёмкость сцепления посчитана без отношения передачи (строка ~452)

```csharp
float capacityAtWheel = engine.PeakTorque * _transmissionSO.ClutchCoef * _transmissionSO.Efficiency;
```

Пропущено умножение на `ratio`. Ёмкость сцепления — величина на стороне мотора
(`ClutchMax = PeakTorque * ClutchCoef`), а сравнивается она с запросом на стороне
колеса. Числа:

```
ClutchMax         = 80.48 * 1.5          = 120.72 Н*м
ёмкость на колесе = 120.72 * 13.797 * 0.9 = 1499    Н*м   (первая)
код считает       = 80.48 * 1.5 * 0.9     = 108.6   Н*м   <- в 13.8 раза меньше
запрос           = (80.48 - 2) * 13.797 * 0.9 = 975 Н*м
```

Код видит `975 > 108.6` и зажимает до 108.6, хотя реальная ёмкость 1499 и зажиматься
нечему. В итоге сцепление в графике практически никогда не работает, а ускорение в
первой передаче занижено примерно в 9 раз.

**Исправить:** ёмкость привести к той же стороне, что и запрос, то есть умножить на
`ratio`. После этого сравнение становится размерно корректным, и зажим сработает
ровно тогда, когда сцепление действительно насыщено.

## Ошибка 3. Кривая передачи не знает про отсечку — рисовать провал явно

Сейчас (строки ~442-448):

```csharp
float wheelOmega  = speed / radius;
float engineOmega = wheelOmega * ratio;
float idleThrottle = Mathf.Clamp01((engine.IdleOmega - engineOmega) * _engineSO.IdleThrottleGain);
float engineTorque   = engine.CalculateTorqueAt(Mathf.Clamp01(Mathf.Max(1f, idleThrottle)), engineOmega);
float engineFriction = engine.CalculateFrictionAt(engineOmega);
```

`engineOmega` не ограничен потолком, и `CalculateTorqueAt` обрезает `rpmNorm` единицей.
Поэтому выше `MaxOmega` момент висит на `PeakTorque` и кривая уходит вправо с
положительным ускорением вечно. В игре там отсечка срезает топливо.

**Требуемое поведение:** при полном газе и `engineOmega >= engine.MaxOmega` момент
сгорания равен нулю — это и есть установившийся режим отсечки. Далее по цепочке:

```
engineTorque   = 0
engineFriction = CalculateFrictionAt(engineOmega)   // остаётся
demand         = (0 - engineFriction) * ratio * Efficiency   // отрицательный
```

Отрицательный момент сцепления тормозит колёса, поэтому ускорение уходит в минус и
провал виден на графике. Величина провала должна сама собой получиться разной по
передачам, потому что торможение двигателем пропорционально отношению: в первой
передаче сильное, в шестой слабое. Это правильно, специально выравнивать не надо.

**Важная оговорка, обязательно отразить в комментарии кода:** график передач —
квазистационарный инструмент, а отсечка в игре переходная (срез 60 мс, возврат
впрыска, дрожь около 6 Гц). Квазистационарная кривая показывает **усреднённую
оболочку** отсечки, а не саму дрожь. Дрожь видна только на белой кривой
`Sim trace`, потому что только она идёт через `Simulate()` по времени.

Если захочется показать провал на кривой передач визуально явнее — можно затем
отдельным решением рисовать вертикальные отметки `MaxOmega` по каждой передаче,
но в этой задаче это НЕ обязательно и делать не надо.

## Ошибка 4. `Simulate()` разошёлся с игрой после задачи 18 (строки ~268-273)

```csharp
float engineTorque = engine.CalculateTorque(1f);
float engineFriction = engine.CalculateFriction();
float clutchTorque = transmission.CalculateClutchTorque(...);
engine.UpdateAngularSpeed(dt, engineTorque - engineFriction - clutchTorque);
```

В игре теперь есть срез топлива (`DriveCarState.cs`, строки 66-68):

```csharp
bool fuelCut = _engine.UpdateRevLimiter(dt, inputData.Throttle);
float engineTorque = _engine.CalculateTorque(inputData.Throttle);
if (fuelCut) engineTorque = 0f;
```

График этой строки не повторяет, поэтому белый «Sim trace» рисует другую физику,
чем едет машина. Пользователь решил просто синхронизировать.

**Сделать в `Simulate()` ровно то же самое**, газ там всегда полный:

```csharp
bool fuelCut = engine.UpdateRevLimiter(dt, 1f);
float engineTorque = engine.CalculateTorque(1f);
if (fuelCut) engineTorque = 0f;
```

И привести в порядок комментарий над `Simulate()` (~строка 228). Сейчас там
утверждается, что порядок вызовов «ровно тот же, что и стейты в игре». После
задачи 18 это стало правдой снова, но утверждение хрупкое: при правке стейтов
этот метод разъедется с ними тихо и незаметно. Добавить в комментарий явное
предупреждение держать синхронизацию при изменении стейтов.

## Мелочь: вводящий в заблуждение комментарий (строка ~251)

Комментарий над прогревочным вызовом утверждает, что мотор «стартует с целевых
холостых без ручной установки». Один вызов `CalculateTorque(0f)` при
`angularSpeed = 0` даёт примерно 134 об/мин, а не 750. Поправить формулировку
на фактическую. Сам вызов не менять.

## Что НЕ трогать

- `EngineService`, `EngineSO`, `EngineModel`, `TransmissionService`, `DrivetrainService` —
  это код игры, не редакторный инструмент. Задача только про `AccelerationGraphWindow.cs`.
- `_maxSpeed`, `_minSpeed`, `StopSpeed`, `CurveSamples`, `DefaultSimDt`, `MaxSimSteps`.
- `CalculateTorqueAt`, `CalculateFrictionAt` и любые методы сервисов — вызывать как есть.
- Формулу `tireForce` в `EvaluateAccelInGear` — она выводится из баланса моментов,
  её корректность здесь не оспаривается.
- Логику `BuildCurves`, `DrawCurve`, `DrawLegend`, `DrawCursorReadout`, оси, палитру.
- Закомментированные строки (правило проекта).
- Сборку НЕ запускать — пользователь запретил. Просто показать итоговый код методов
  `EvaluateAccelInGear` и `Simulate` целиком.

## Критерии приёмки

- Подсказка показывает реальный потолок: `RPM: 5826 (max 7500)`, а не `(max 225)`.
- Ёмкость сцепления в кривой передачи умножается на `ratio` и сравнивается
  в одной размерности с запросом.
- Кривая передачи после `MaxOmega` уходит в отрицательное ускорение, и величина
  провала различается по передачам (сильнее в низких, слабее в высоких).
- `Simulate()` вызывает `UpdateRevLimiter(dt, 1f)` и обнуляет момент при срезе —
  порядок вызовов совпадает с `DriveCarState.Tick`.
- Комментарий над `Simulate()` больше не ложный и предупреждает о необходимости
  держать синхронизацию.
- Подпись метода `EvaluateAccelInGear` упоминает, что кривая квазистационарная и
  показывает усреднённую оболочку отсечки, а не дрожь.
- Ни один файл вне `AccelerationGraphWindow.cs` не изменён.
- Файл `AccelerationGraphWindow.cs` целиком в `#if UNITY_EDITOR`.
- Сборка не запускалась.
