# Task 16 — `TachometerController`: убрать фильтр на 0.5 с, починить шкалу

## Проблемы (три независимые, все в одном файле)

### 1. Временный лог пользователя

`Debug.Log(rpm)` на строке 52 — отладочный, добавлен для диагностики. В релизе
такого быть не должно. Удалить.

### 2. Шкала короче реальных оборотов

```csharp
[SerializeField] private float MAX_RPM = 9000;
```

При этом `EngineService.MaxRPM = 7500`, а модель (до task 15) давала до 10 125.
`Mathf.Clamp01(normalizedRpm)` срезает всё выше шкалы в единицу, стрелка упирается
в упор и стоит. Пользователь наблюдает ровно это: «стрелка застревает на 9к».

`MAX_RPM` должен браться у двигателя, а не быть зашитым числом.

### 3. `DORotate(..., 0.5f)` перезапускается каждый кадр

```csharp
arrow.DORotate(new Vector3(0, 0, zAngle), 0.5f);
```

Каждый физический кадр новый tween на 0.5 с, предыдущий не отменяется. Стрелка
физически не может отрабатывать быстрее этого сглаживания — реальные обороты падают
примерно на 200 об/мин за кадр, а стрелка едет по фильтру в полсекунды. Пользователь
это видит как «очень медленно снижается».

Плюс риск зависания на переходе через `-180°`: `minMaxAngle = (-45, -247)`,
диапазон пересекает `-180`, а `DORotate` работает с эйлеровыми углами. Если угол
стрелки уже завернул за `-180`, цель и текущее значение сравниваются как разнородные
углы и tween может не найти направление.

## Что сделать

1. Удалить `Debug.Log(rpm)`.
2. Убрать `DORotate` из горячего пути. Угол задавать напрямую:
   ```csharp
   arrow.transform.rotation = Quaternion.Euler(0f, 0f, zAngle);
   ```
   `zAngle` всегда лежит в непрерывном диапазоне `[minMaxAngle.y, minMaxAngle.x]`,
   поэтому абсолютное присваивание эйлера однозначно и проблемы зависания нет.
   Проверить, станет ли `using DG.Tweening;` неиспользуемым — если в файле не
   осталось других вызовов DOTween, using убрать.
3. Вместо tween-фильтра сделать короткое сглаживание внутри самого метода, с
   частотонезависимым коэффициентом. Тайм-константа в районе 0.05–0.08 с: стрелка
   остаётся читаемой, но не «врёт» полсекунды. Плавность должна быть параметром
   с дефолтом, а не магическим числом в формуле.
4. Состояние сглаживания должно обнуляться, чтобы при первом вызове стрелка не
   перелетала через весь диапазон из начального положения. Инициализировать текущим
   значением RPM на первом вызове либо отдельно в `Start`.
5. `MAX_RPM` брать из двигателя, а не из инспектора. Двигатель доступен через
   `TransmissionService` либо через прямую инъекцию `EngineService` в `Construct`
   (VContainer резолвит его автоматически, он уже зарегистрирован как зависимость
   `TransmissionService`). Выбрать один вариант и не заводить второй источник правды.
6. `MIN_RPM = 0` оставить.
7. В `Start` стоит жёстко зашитый `-45`:
   ```csharp
   arrow.transform.rotation = Quaternion.Euler(new Vector3(0, 0, -45));
   ```
   Это дублирование `minMaxAngle.x`. Заменить на `minMaxAngle.x`, чтобы при
   изменении диапазона в инспекторе начальное положение ехало вместе с ним.
8. Закомментированные строки в файле не трогать. Поля `_car`, `_transmission`
   не удалять — `_car` используется в закомментированной строке, удаление сломает
   её актуальность.
9. `UpdateGearDisplay` не трогать.

## Критерии приёмки

- В файле нет ни одного `Debug.Log`.
- `DORotate` в файле отсутствует.
- `MAX_RPM` не является магическим числом 9000; значение шкалы соответствует
  `EngineService.MaxRPM`.
- Стрелка реагирует на изменение RPM в пределах одного кадра плюс сглаживание,
  а не за 0.5 с; задержка визуально не превышает ~0.1 с.
- При RPM выше `MAX_RPM` стрелка упирается в упор, но `EngineService` уже не даёт
  таких оборотов (task 15), то есть упор недостижим в нормальном движении.
- `minMaxAngle` пересекает `-180`, и при проходе стрелки через эту точку нет
  зависания и прокрутки на 360°.
- `Start` не содержит зашитого `-45`, использует `minMaxAngle.x`.
- `dotnet build Assembly-CSharp.csproj` — 0 ошибок, новых предупреждений нет.
- `dotnet build Assembly-CSharp-Editor.csproj` — 0 ошибок, новых предупреждений нет.
